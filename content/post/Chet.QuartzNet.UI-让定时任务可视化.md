凌晨两点半，数据同步任务失败了。

没有告警，没有日志，没有一个人知道。第二天早上业务方打电话过来，说昨天的报表是空的——你打开服务器，翻了一圈 `quartz` 的日志文件，才发现那个任务从上周五就已经在静默地报错。

定时任务这件事，写起来三行代码，维护起来却能要人命。

<!--more-->

## 定时任务的三个老毛病

**第一，看不见。**

任务跑没跑、跑了几次、失败几次、下次什么时候跑，全靠猜。想看一眼，就得 ssh 上去翻日志。

**第二，改不动。**

产品经理说这个任务要从每天两点改成每十分钟，你改代码、重新发布、重启服务。为了一个 Cron 表达式，走了一整套发布流程。

**第三，出事没人管。**

失败了不通知，通知了不重试，重试了不记录。等到业务方发现数据不对，黄花菜都凉了。

## 所以我做了 Chet.QuartzNet.UI

它的定位很直接：**给 Quartz.Net 补一个能看、能改、能告警的可视化后台，安装成本压到一个 NuGet 包。**

```bash
dotnet add package Chet.QuartzNet.UI
```

然后在 `Program.cs` 里加三行：

```csharp
builder.Services.AddQuartzUI(builder.Configuration);
builder.Services.AddQuartzClassJobs();

var app = builder.Build();
app.UseQuartz();
```

启动后打开 `/quartz-ui`，作业列表、执行日志、监控图表全都在了。文件存储模式下零数据库依赖，克隆下来就能跑。

## 它具体能干什么

- **作业管理**：新增、编辑、暂停、恢复、立即执行、批量操作，不用再写配置文件
- **Cron 表达式**：在线编辑，改完即时生效
- **执行日志**：完整的执行历史、耗时、错误信息，还有「已跳过」状态
- **失败重试**：不用自己包一层 try-catch 和循环
- **实时监控**：KPI 卡片、健康象限、时段热力图、耗时排行
- **多渠道通知**：基于 PushPlus，微信、企业微信、钉钉、邮件都能触达
- **作业依赖**：前置作业全部成功才执行，轻量版工作流
- **存储自由**：文件 / MySQL / PostgreSQL / SQLite / SQL Server，五种存储任意互转

我最喜欢的是「数据迁移」这块。很多调度框架一开始用文件存储图省事，等项目长大了想换数据库，就得自己写迁移脚本。这里预检、备份、进度、迁移后校验都做进界面了，点几下就行。

## 代码和界面不打架

有一种情况很常见：作业是写在代码里的，但运维又想在界面上改。

`[QuartzJob]` 特性就是为这个准备的——作业类打上标记，启动时自动扫描注册，同时还能在 UI 里管理。代码和界面不是二选一，而是同一套东西的两种入口。

## 适合谁

- 中小项目想快速拥有一个能用的调度后台
- 已经用 Quartz.Net，但受够了没有界面的团队
- 不想为了一个定时任务引入一整套重型调度平台的人

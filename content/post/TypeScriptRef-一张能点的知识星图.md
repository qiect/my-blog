TypeScript 的学习曲线很有意思。

入门很顺：给变量加个类型，函数参数写上 `: string`，感觉就是"带类型的 JavaScript"。

然后你遇到了泛型，遇到了 `keyof`、`infer`、条件类型、映射类型，突然发现这玩意儿和 Java 完全不是一回事。再然后看到别人代码里一行：

```ts
type DeepPartial<T> = { [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K] };
```

你盯着看了两分钟，决定还是用 `any`。

<!--more-->

## 问题不是难，是散

TypeScript 的官方文档其实写得不差，但它是**线性**的：按章节顺序往下读，读完第二章忘了第一章。

而实际开发中遇到的问题，从来不是线性的。你可能是"泛型约束怎么写"和"模块解析为什么报错"同时卡住，需要的是能跳着查、能看清楚知识之间关系的东西。

## 所以有了这张星图

TypeScriptRef 的核心是一个**知识星图**：把 TypeScript 的知识点做成一张网络，点节点就能进去。

它覆盖了这些板块：

- 入门与基础类型
- 接口
- 函数
- 类
- 泛型
- 高级类型
- 模块
- 枚举
- 装饰器

每个板块都配了教程和速查表两条路径：

- **想系统学**：走教程，一步步往下看
- **想马上用**：走速查表，直接找到那个语法的写法

## 速查表才是日常刚需

说实话，绝大多数时候我们不需要"学会"某个知识，只需要"想起来"它怎么写。

比如：

- 交叉类型和联合类型怎么组合
- `Pick`、`Omit`、`Record` 怎么套
- 泛型默认值和约束写在哪
- 模块的 `import type` 什么时候用

这些问题的答案都在速查表里，一页能看完，不用翻三篇博客。

## 一点设计上的想法

知识星图这个东西，表面上是好看，实际解决的是**"我不知道我不知道什么"**。

看书的时候，你只能看到目录里有的东西。看星图的时候，你会发现某个节点旁边还连着七八个你没见过的概念——这种"原来还有这个"的发现感，是很难靠目录给到的。

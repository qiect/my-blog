每次开新项目，前三天都在干同一件事：搭架子。

建分层目录、配 JWT、写刷新令牌、接 EF Core、挂 Redis、装 Serilog、统一返回格式、处理全局异常……等这些弄完，业务代码一行还没写，人已经累了。

更难受的是，每个项目搭出来的架子都不太一样。A 项目用 `Result<T>`，B 项目返回裸对象；A 项目令牌过期时间 30 分钟，B 项目写了 2 小时。半年后回头看，全组有八种"标准"。

<!--more-->

## 把经验固化成生成器

Chet.Web.Template 做的事情很简单：**你把公司名和项目名填进去，它把所有该有的东西一次性搭好。**

打开生成页面，填三个东西：

- 公司 / 组织名称
- 项目名称
- 架构模板（目前是单体 Web API 模板）

点一下「开始构建并下载」，一个能直接 `dotnet run` 的 .NET 10 项目就下来了。

## 生成出来有什么

- **分层架构**：Application、Core 等模块职责清晰，不是把所有代码塞进一个文件夹
- **JWT 认证**：登录、鉴权、刷新令牌一条链路打通
- **基于角色的授权**：角色和权限的骨架直接可用
- **EF Core**：数据访问层开箱即用，内置 SQLite，本地跑起来零配置
- **Redis 缓存**：缓存接入已经写好，不用再抄一遍配置
- **Serilog**：结构化日志，请求日志和异常日志分开
- **统一规范**：返回结构、异常处理、配置分层都按同一套约定来

## 为什么值得用

脚手架这个东西，价值不在"省了多少行代码"，而在**统一**。

十个人从零搭十个项目，就会有十种风格。十个人用同一个生成器，出来的骨架至少骨架是同一个——新人进项目组，看一个项目就能看懂其他项目。

另外，.NET 版本升级是个长期问题。官方模板给的是最朴素的东西，认证、缓存、日志这些生产必备件都得自己补。生成器的意义就是把这些"补丁"提前打好，让新项目从第一天起就是生产形态。

## 适合谁

- 经常开新项目、被初始化工作反复折磨的团队
- 想统一团队技术底座，但不想维护一套重型框架的人
- 用 .NET 8 / .NET 10 做后端，习惯分层架构的开发者
